# 旧 `post-comment.zip` 実ファイル監査

調査対象：提供された旧 `post-comment.zip` 内の `user.php`。ファイル名はUTF-8のZIP内パスとして復元し、比較用にUnicode NFCへ正規化。**旧 `.env` の秘密情報は読み出し・記録・コミットしない。**

## ファイル数と種類

`user.php` は合計20個。うち `template` 1個、移行対象外の `5dlab_old` 1個を除く**18ルーム**が移行対象。

| SHA-256先頭12桁 | 個数 | 意味 |
|---|---:|---|
| `cdbb3d80ae6c` | 10 | 標準フォームと同じ投稿項目。案内文の誤字「性」と送信エラー文の修正差分 |
| `dac73c3b65ff` | 7 | 現行標準テンプレートと同一。うち1個は `template/user.php` |
| `152e628346e3` | 1 | `guest`：名前＋コメントの簡易フォーム |
| `8640bfa39f50` | 1 | 研究基盤EXPO：標準フォームの所属欄表示を「所属」に短縮し、旧セッション検証をコメントアウト |
| `aeab5efb1276` | 1 | `5dlab_old`：除外 |

したがって、実ルーム18のうち**標準16、guest1、研究基盤EXPO1**と分類できる。

## 移行で扱う差分

- 標準フォームの入力項目：姓（必須）、名（必須）、所属（必須）、メール（任意）、コメント（必須）。姓・名・所属・メール・コメントの日本語／英語プレースホルダーを標準フォームに反映
- `guest`：表示ラベル「名前」と「コメント」。新仕様では認証なしルームとし、本人CSVは匿名セッションで絞り込む
- 研究基盤EXPO：所属欄「所属」、認証なし。旧コードの認証バイパスをそのまま再現するのではなく、ルーム設定で認証なしを明示
- 標準フォーム内の旧案内文「氏名と所属の完全一致でログを取得」は、新仕様の本人認証方式と矛盾するため置換
- 旧投稿の本人ID推定・紐付けは行わず、CSVインポートで履歴として保存
- ルーム名の特殊文字、NFC/NFD、階層構造に注意。新URLは英小文字の専用識別子を使い、旧URL維持は不要

## 未検証

この監査は **旧 `user.php` のコードと表示テキストの差分**を対象とする。旧MySQLの実データ、すべての `admin.php` 等の運用上のルーム固有変更、現場のURL動作、実サーバー環境を検証したものではない。実データ移行後の投稿件数・時刻・本文・項目照合が必要。

## 投稿・管理APIの実ファイル差分

旧ZIPの `index.php` / `admin.php` / `save.php` / `load.php` / `download.php` を、ルーム別にSHA-256で比較した。各ファイルは**18ルーム中17が共通、1がguest型**である（`template` と `5dlab_old` は集計から除外）。したがってルームごとの個別投稿APIは確認されず、標準機能とguest例外に分離して新システムへ取り込む方針が妥当。

ただし、同一コードであることは、古いMySQLデータ内に特殊な入力値や欠損がないことを証明しない。実データの移行検査は別途必要。
