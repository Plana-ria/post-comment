# Post Comment セットアップマニュアル（開発版）

> 現在は開発版です。実際の授業・イベントの個人情報を扱う本番サイトへは、受け入れ試験完了まで設置しないでください。

## 事前に確認すること

サーバーに **PHP 8.3以降**、**PDO_SQLITE**、**HTTPS** が必要です。SSH、root権限、Composerの実行、MySQLデータベースの新規作成は必要ありません。ファイルマネージャーまたはFTPでファイルをアップロードできることを確認してください。

SQLiteのファイルロックが正常に動作する保存領域が必要です。ネットワークファイルシステムで正常なロックを保証できないサーバーは対象外です。

## A. DocumentRootを変更できるサーバー

配布ZIPの `post-comment-private/` の中身を非公開のアプリディレクトリに配置し、`public/` の中身だけをWeb公開ディレクトリに配置します。公開ディレクトリがアプリ本体の直下にある場合、通常は自動で検出されます。

## B. DocumentRootを変更できない一般的なレンタルサーバー

例：

```text
/home/example/
├── post-comment-private/       ← Webからアクセス不可
│   ├── src/
│   ├── database/
│   ├── storage/
│   └── config.example.php
└── public_html/
    └── comment/                ← ブラウザでアクセス
        ├── index.php
        ├── install.php
        ├── restore.php
        ├── bootstrap.php
        ├── assets/
        └── .htaccess
```

配布ZIPの `post-comment-private` フォルダをユーザーのホームディレクトリ（Web公開領域の外）へ置き、配布ZIPの `public` の中身を `public_html/comment/` にアップロードします。

設置先が特殊な場合のみ `public/location.php` を作り、PHPの `return '/home/example/post-comment-private';` として非公開フォルダの絶対パスを指定してください。**`config.php` や `storage/` を `public_html` に置かないでください。**

## 初回インストール

1. `https://example.com/comment/install.php` を開きます。
2. 「設置確認コードを生成」を押し、64桁の文字列をコピーします。
3. サーバーのファイルマネージャーまたはFTPで、非公開の `post-comment-private/storage/install-proof.txt` を作り、先ほどの文字列だけを書き込みます。
4. 設置URL（例：`https://example.com/comment`）、管理者ID、管理者認証文字列を入力します。
5. 「インストール」を押します。設定ファイルとSQLite DBが自動作成されます。
6. 管理者ログイン画面からログインし、ルームを作成します。

初回設定が完了すると `install-proof.txt` は削除され、インストール画面は再実行できなくなります。

## 日常運用

管理者はルームを作成し、認証あり／なしと標準／簡易フォームを指定します。ルームの受信画面からフォーム編集、ルーム停止・再開、CSV取得、利用者のコード再発行を行います。システム管理者は「システム保守」からDBのバックアップを取得・復元できます。

## 別サーバーへの移行

1. 旧サーバーで新しい投稿を停止し、管理画面の「システム保守」からSQLiteのバックアップをダウンロードします。
2. 新サーバーで上記の手順に従い、空のシステムを新規インストールします。
3. 新サーバーの「システム保守」→「DBを復元」から旧バックアップをアップロードします。
4. 再ログインし、ルーム・投稿数・フォーム設定を確認します。
5. 新サーバーのURLが正しく動作したことを確認した後、旧サーバーの運用を終了します。

移行ファイルには個人情報や認証情報のハッシュが含まれます。公開領域や共有ストレージに置かず、安全に扱ってください。バックアップの復元はSQLite DBとその内部設定を置き換えますが、移行先固有の `config.php` は変更しません。

## アプリの更新

現在、GitHub Releasesからのアプリ本体のワンクリック更新は未実装です。開発版の手動更新では、DBのバックアップを取ってから配布ZIPのコードファイルを上書きし、必要に応じて `?route=db-upgrade` でDBを更新します。`config.php` と `storage/` は上書きしません。更新失敗時にデータが失われないよう、正式な更新機構が完成するまでは運用担当者だけで本番更新しないでください。

## 動かない場合

- 「PDO_SQLITEが必要」：ホスティングのPHP拡張設定を確認
- 「保存領域を開けない」：非公開 `storage/` フォルダのPHP書き込み権限を確認
- 「非公開アプリ本体が見つからない」：FTPの配置と `location.php` を確認
- 「Web公開領域にある」：`src/`、`database/`、`storage/` 等をWeb公開領域の外に移動
- 「メンテナンス中」：復元や更新処理が終了してから再試行
