# Post Comment — アーキテクチャ・セキュリティ設計

## ファイルと責任
- `public/`: Web公開エントリポイント（`index.php`, `install.php`, `restore.php`, `update.php`, `emergency-recover.php`）と安全な静的アセット。
- `src/`: ルーティング・DB処理・フォーム・認証・CSV・移行・更新・復元サービス。HTMLでは `htmlspecialchars` を使用し、SQL値はPDOプレースホルダを使用する。
- `database/migrations/`: 順序付き・チェックサム記録の不可逆スキーマ移行。
- `config.php`, `storage/`: ホスト固有・非公開。配布やGitには含めない。

## データモデル
`users` と `administrators` は別の認証主体。参加者のID・コードは全ルーム共通。ルーム別の管理権限は `admin_room_roles`、参加状態は `room_participants`。投稿 `comments` は `rooms`, `form_versions` を参照し、登録済ユーザーID、匿名セッションID、または歴史的未関連レコードを保持する。投稿時の回答はJSONで保持し、フォーム版は変更せず新規追加する。公開フォームと下書きは独立。

厳密なテーブル構造・索引・制約の正本は `database/migrations/*.sql`。この文書に固定テーブル定義を重複させない。

## 認可境界
1. PHPセッションCookieはSecure（HTTPSの場合）、HttpOnly、SameSite=Lax、ログイン時再生成する。
2. 管理者のロール・有効状態・認証バージョンは毎回DBで確認する。
3. 担当ルームの認可は一覧・受信・新着JSON・CSV・フォーム更新・認証再発行の各入口で個別に確認する。
4. POST変更操作にはCSRFトークンを要求し、GETでは原則状態を変更しない。
5. 匿名CookieはランダムトークンのハッシュだけをDBへ保存。期限切れの識別子から過去投稿を取得できない。
6. 旧データは姓名・所属等の一致では新ユーザーに結び付けない。

## 更新・復旧の信頼境界
- 署名検証用Ed25519公開鍵はサイトの非公開設定で固定。秘密鍵はGitHub Secrets等の安全な保管先に置き、Gitへコミットしない。
- ZIPのバイト列SHA-256に対する署名を検証し、パスのエスケープ・リンク・サイズ超過・未知の置換対象を拒否する。
- 更新前にSQLiteの整合性検証付きバックアップと既存コードを退避し、メンテナンスロックの下で切替・マイグレーション・検証を行う。異常時はロールバックし、復旧不能時は保守フラグを残して停止する。
- 非公開バックアップ復元時は物理整合性、外部キー、スキーママイグレーションの互換性を確認する。
- エンジニア非常復旧は非公開の使い捨て証明ファイルを利用。使用済み証明は削除し、認証情報を一度だけ表示する。
