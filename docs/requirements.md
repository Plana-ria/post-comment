# Post Comment 再設計 — 確定機能要求

## 目的と対象
授業、講演、イベントなどで参加者が質問やコメントを送信し、担当管理者が受信・確認・CSV出力できる。非エンジニアがブラウザからルーム・フォーム・管理者・運用を管理できることを最優先にする。

**対象環境:** PHP 8.3以上とPDO_SQLITEを利用できる一般的な共有レンタルサーバー。SSH/root/Composer・Nodeのサーバー上実行/Docker/cronを必須にしない。機微情報は公開フォルダー外の単一SQLiteと設定ファイルへ保存する。

## 利用者と認証
- 認証あり・なしをルーム作成時に選択する。ルーム共通パスワードは使用しない。
- 認証ありルームでは参加者が初回アクセス時に自由登録し、ランダムなユーザーIDとログインコードを受け取る。組み合わせは複数ルーム・端末で共通。自動リンクや氏名の一致による本人認証はしない。
- ルーム管理者は対面で利用者コードを再発行でき、旧コードと旧セッションを失効させる。過去投稿は残す。
- 匿名ルームは登録不要。ブラウザに期限付きの不透明なCookieを保存し、期限内に同一ブラウザから自分の投稿を取得できる。別ルームの匿名IDや登録済ユーザーIDと自動関連付けしない。

## 投稿・ルーム
- 送信時のフォーム定義を版として保持し、すべてのコメントに当時のフォーム版と回答を結び付ける。
- コメント本文に相当する1項目が必須。フォームで表示名や入力部品・項目順・必須条件・説明・選択肢を変更できる。下書き保存、プレビュー、公開、版履歴を提供する。
- 利用者は送信済コメントを編集・削除できない。再読み込みで二重送信しない。閉鎖済みルームは新規投稿を受け付けない。
- ルーム管理者には担当ルームの受信一覧と新着自動取得、フォーム編集、CSV出力、コード再発行を許可する。他ルームは閲覧も操作も禁止。
- システム管理者は複数人設定可能で、ルーム管理者の担当ルームを設定・解除し、管理者アカウントを停止・再有効化できる。最後の有効なシステム管理者の削除・降格を防ぐ。

## ダウンロード
- **参加者用CSV:** 自分が提出した投稿に限り、`time,comment` の2列のみを出力。フォーム内に入力した氏名・所属・メールや回答項目を自動追加しない。コメント本文に個人情報が書かれていても機械的に削除しない。
- **管理者用CSV:** ルームの全投稿を対象に、従来の氏名・所属・メール・コメント等の項目と、新旧のカスタムフォーム回答を残す。旧標準ヘッダー互換と日本時間表記を優先。
- CSVインジェクションを防ぎつつ、DB内部の元入力値は変更しない。

## 旧版移行
- 提供された旧 `post-comment.zip` の対象ルーム（18ルーム）から名称・フォーム差分・コメント履歴を移す。明示的に **`5dlab_old` を除外**。
- 過去投稿と新しい登録ユーザーを推測で紐付けず、投稿日時・本文・回答を履歴として保持する。
- 旧管理者CSVのUTF-8/CP932と改行・引用符・カンマを含む値を扱う。再インポート時に同一ファイル内の投稿を重複させない。

## 設置・運用
- Web公開ディレクトリの変更ができない環境にも対応し、公開コードと非公開コード・DB・バックアップを分離する。
- ブラウザ設置、バックアップ・復元、システム診断、サーバー移転、署名付きGitHub Releases更新を支援。
- アップデート前にDB・コードを退避し、失敗時に復旧する。エンジニアが非公開ファイルを設置する非常管理者復旧手段を持つ。恒久的な共通マスターパスワードは設けない。
