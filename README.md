# Post Comment — 再設計版

講義・授業・イベント向けコメントルームを、**PHP + SQLite** で運用するWebアプリケーションです。

> **現在は本番受入前の開発版です。** 主要機能とPHP/HTTP結合テストは実装済みですが、共有レンタルサーバー実機での設置・移行・更新失敗試験、正式署名鍵の運用、旧MySQL実データの移行照合が未完了です。個人情報を扱う本番サイトへの置き換えは、[リリース受入確認](docs/release-readiness.md)を完了するまで控えてください。

## 利用者向け機能

- **ルーム**：管理者がルームを作成し、認証あり／なし、名称、投稿受付状態を設定。ルームごとにPHPやDBテーブルを複製しません。
- **参加者認証**：初回に自由登録。1組のシステム発行ユーザーID＋ログインコードを複数ルーム・複数端末で利用。管理者がコードを再発行すると旧コード・旧セッションは無効。
- **匿名ルーム**：ログイン不要。ブラウザの期限付き識別Cookieを使い、同じブラウザから本人の投稿ログを取得可能。
- **投稿**：必須のコメント本文と、ルーム別に定義したフォーム入力を保存。送信後に一度だけ完了表示し、再読込で二重送信しません。
- **フォームビルダー**：ラベル、補足説明、プレースホルダー、必須条件、テキスト／メール／テキストエリア／選択式／チェックボックス、選択肢、表示順、下書き、プレビュー、公開版を管理。投稿時のフォーム版は保持します。
- **管理者受信画面**：担当ルームの投稿を確認。約3秒間隔で新着取得し、参加者コードを再発行。
- **CSV**：参加者用は**`time,comment` の2列だけ**。管理者用は旧形式互換の氏名・所属・メール・コメント列およびカスタム項目を含めます。参加者に他の利用者の個人情報を出力しません。
- **権限**：システム管理者と、担当ルームに限定された複数ルーム管理者。管理者の追加・停止・役割変更・担当割当。
- **日常運用**：SQLiteの一貫したバックアップ、ブラウザ復元、環境診断、ルーム設定の変更、管理者の認証再発行。
- **旧版移行**：旧ZIPで確認した18ルームの基本設定移行と、旧管理者CSVの重複防止付き取込。旧 `5dlab_old` は対象外。旧投稿と新ユーザーIDを自動連結しません。
- **アップデート**：GitHub Releasesからの取得または手動ZIPアップロード。Ed25519署名検証後にコード・SQLiteをバックアップして適用し、失敗時の復旧を試みます。初回の信頼鍵設定と実機耐障害試験が必要です。

## 簡単な設置手順

1. PHP 8.3以降、PDO_SQLITE、mbstring、HTTPS、書込可能な非公開領域、正常なファイルロックを備えたサーバーを用意。署名付き更新にはさらにPHP zip・sodiumを使用します。
2. 配布パッケージの `post-comment-private/` を**Web公開領域の外**に、`public/` の中身だけを公開ディレクトリへ配置。
3. `https://設置先/install.php` を開き、画面の設置確認コードを生成。
4. 非公開 `storage/install-proof.txt` に表示されたコードを置き、管理者ID・認証文字列とURLを設定してインストール。
5. 管理者ログイン後、ダッシュボードからルーム作成・フォーム編集・受信画面を利用。

DocumentRootを変更できない共有レンタルサーバーでも、公開・非公開フォルダを分離できる場合の設置手順を用意しています。詳しくは[設置マニュアル](docs/SETUP.md)を参照してください。

**決して公開しないもの**：`config.php`、`storage/`、SQLiteファイル、バックアップ、署名秘密鍵、旧システムの`.env`。公開するのは`public/`のファイルだけです。

## 管理と復旧

- 管理ダッシュボード：担当ルーム一覧、新規ルーム、管理者管理、システム保守へのリンク
- システム保守：バックアップ／復元／環境診断／旧ルームひな形移行／署名付き更新
- 管理者の認証紛失：ログインできるシステム管理者が再発行。全員が認証情報を紛失した場合は、エンジニアが非公開の一時証明ファイルを設置して`emergency-recover.php`から復旧
- サーバー移転：旧サーバーで投稿を停止し、DBをバックアップ。新サーバーを新URLで設置後、DBを復元し、ルームと投稿を確認

[運用・非常復旧手順](docs/OPERATIONS.md)

## 開発・検証

- PHP 8.3/8.4でPHP構文チェックと`php tests/smoke.php`を実行
- `python3 tests/http_smoke.py`：PHP組み込みサーバーを使い、初回セットアップ、ログイン、投稿・CSV、認証方式、管理者の担当ルーム制限を検証
- 並行投稿テスト：`python3 tests/parallel_sqlite.py` で8プロセス96投稿の件数・整合性を確認
- 更新テスト：テスト用の署名付きZIPを適用し、コード切替・DB保持・保守フラグ解除、SQL移行失敗時の復旧と危険なZIPの拒否を確認
- [旧コードとの差分監査](docs/legacy-source-audit.md) / [旧機能対応表](docs/legacy-feature-matrix.md) / [本番受入チェックリスト](docs/release-readiness.md)

CIの成功は本番環境での無条件の安全性や全機能の受入完了を意味しません。未完了の必須検証は[リリース受入確認](docs/release-readiness.md)に記録します。

## 技術・配布

サーバー上でSSH・root権限・Composer・Node・Docker・cron・常駐プロセスは必須ではありません。配布用ZIPはGitHub Actions `Portable distribution` で生成し、正式リリースには署名付きZIPと`.sig`を添付する設計です。

MITなどのライセンスは現時点では明示的に付与されていません。リポジトリを第三者へ再配布する場合は権利関係を確認してください。
