# Post Comment — 再設計版（開発中）

講義・イベントのコメント投稿ルームをPHPとSQLiteで運用するシステムです。

> **現在は初期実装段階です。** DBスキーマ、初回管理者セットアップ、管理者ログイン、ルーム作成、ユーザーID・コード、標準フォームでの投稿、CSV出力の初期版まで実装しています。フォーム編集・複数管理者の初期画面、ログイン試行制限、管理画面からのDBバックアップ取得、管理者認証情報の再発行を追加しましたが、旧CSVデータのインポート初期版に対応しましたが、旧ルーム設定の自動移行、GitHub自動更新、幅広いレンタルサーバー向け完成版の配布は**未実装**です。既存サービスの置き換えには使用しないでください。

## 基本方針

- PHP + PDO_SQLITE。root権限、SSH、Composerのサーバー実行、cronは必須にしない。
- SQLiteにルーム・ユーザー・コメントを一元化。ルームごとにPHPやDBテーブルを複製しない。
- 個人認証あり／なしをルーム別に選べる。認証ありは全ルーム共通IDとシステム発行コード。
- 参加者用CSVはタイムスタンプとコメントのみ。管理者用はフォーム回答全体。
- `5dlab_old` は移行対象外。

## 開発段階の起動方法（安全な環境のみ）

**重要:** 公開するのは `public/` のファイルだけです。DocumentRootを変更できないレンタルサーバーでも、公開用ファイルと非公開の `post-comment-private/` を別フォルダに配置する構成に対応しました。詳細は [セットアップ手順](docs/SETUP.md) を参照してください。

1. PHP 8.3以上、`PDO_SQLITE`、HTTPSが利用できるサーバーを用意する。
2. `public/` だけをWeb公開領域として配置し、`storage/` とアプリのルートはWebに公開しない。
3. `storage/` とアプリのルートに、PHPからの書き込み権限を付与する。
4. ブラウザで `install.php` を開き、画面のボタンで64文字の設置確認コードを生成する。
5. サーバーのファイルマネージャー等で、表示されたコードを `storage/install-proof.txt` に書き込む。
6. 画面で設置URL、管理者ID、認証文字列を設定してインストールする。
7. SQLiteと `config.php` は自動生成され、設置確認ファイルは成功時に削除される。

**重要:** DocumentRootの変更権限がない場合も、Web公開領域外に `post-comment-private/` を配置できれば構成可能です。共有レンタルサーバー実機での動作検証は引き続き必要です。

PHP組み込みサーバーでのローカル動作確認例（**本番利用不可**）:

```sh
php -S 127.0.0.1:8080 -t public
```

本番運用可能と判断するには、ファイルロック・公開領域の保護・権限・セッション・更新・復元などの実機検証が必要です。

## 管理画面の運用機能（開発中）

- `?route=operations`：システム管理者のみ利用可能。SQLiteの整合性を確認したバックアップをダウンロードする。
- `?route=operations`：システム／ルーム管理者の認証情報を再発行する。旧認証情報は無効となる。
- `?route=db-upgrade`：既存DBに未適用のマイグレーションがある場合、システム管理者がバックアップ後に更新する。
- バックアップには参加者の個人情報・ログイン認証情報のハッシュを含む。ダウンロードしたファイルの共有・保管には注意すること。

管理画面からSQLiteバックアップをアップロードして復元する初期版を追加しました。復元前に現在のDBを保存し、リクエスト排他ロックとDBの整合性・マイグレーション履歴の検証を行います。復元後はログインし直す必要があります。PHPのアップロード上限に加えて128MBのアップロード制限があります。大規模データでの復元試験と共有レンタルサーバーの実機検証は未実施です。

## 開発状況とテスト

`php tests/smoke.php` と GitHub Actions の PHP 8.3 / 8.4 チェックを利用しています。
これらは自動化された機能テストであり、ブラウザE2E試験、サーバー移植試験、脆弱性診断が完了したことを意味しません。


### 復元に関する注意

通常のリクエストは `storage/maintenance.lock` に共有ロックを取り、DBの復元処理だけは排他ロックを取得します。サーバーのファイルロックが安全に使えることが前提です。SQLiteのDBファイルと `config.php` を公開領域内に配置しないでください。復元したDBには個人情報と認証情報のハッシュが含まれます。


## 初回セットアップ（ブラウザ方式）

`install.php` では、サーバー側のファイル操作権限を確認するため、Web非公開の `storage/install-proof.txt` に秘密の確認コードを配置します。これにより、最初にURLを見つけた第三者が勝手にシステム管理者になることを防ぎます。コードはブラウザ内で生成され、サーバー側で自動発行したパスワードではありません。設置済みのサイトではインストーラーが無効化されます。

## 旧コメントCSVの取り込み

旧システムの管理者画面から全件CSVをダウンロードし、新システムで対象ルームを作成してから、受信画面の「旧CSVを取り込む」からアップロードします。標準形式（`time,last_name,first_name,affiliation,mail,messenge`）と旧 `guest` 形式（`time,name,messenge`）に対応します。CSV中の旧時刻は日本時間として解釈し、内部ではUTCに変換します。インポートはトランザクション処理で、同じCSVを二度取り込んでも同じ行を再登録しません。既存の投稿と新しいユーザーIDは紐付けません。

旧ルーム固有の文言・フォーム差異をPHPコードから抽出する自動移行は未実装です。管理者は必要に応じてルームフォームを編集してください。`5dlab_old` は移行対象外です。


## ルーム管理と投稿制限

ルーム管理者は受信画面からルーム名と投稿受付状態（受付中・終了）を変更できます。認証方式とURL識別子は投稿履歴の取り違えを避けるため作成後は固定します。登録済み参加者は投稿前からルームのユーザー一覧へ登録され、コード再発行の対象にできます。過剰な自動登録・認証試行・連続投稿への制限をSQLiteで行います。

## エンジニア向け非常復旧

システム管理者全員が認証情報を紛失した場合、エンジニアがFTPまたはファイルマネージャーで、Web公開領域外の `storage/emergency-proof.txt` に**暗号学的にランダムな64桁の小文字16進数**を1行書き込みます。ファイルを作った後に `https://設置先/emergency-recover.php` を開き、同じコードを入力して対象のシステム管理者を選択すると認証コードを再発行できます。成功時には復旧証明ファイルを自動削除し、旧認証情報とセッションは失効します。

この復旧コードはGitHubや管理画面の設定に保存しないでください。固定のマスターコードや通常利用できる裏口は存在しません。`storage/` はWeb非公開であることが必須です。
